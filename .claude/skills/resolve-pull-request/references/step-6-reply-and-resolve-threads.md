# Step 6 — Reply to and Resolve Threads

When party-mode's review **accepts** the changes for a comment, push the branch. Then reply to that comment's thread and resolve it.

## Push the changes first

```bash
git push           # push the accepted commits to the PR head branch
```

Push before you reply. Then people can already see the work on the PR when they read your reply.

## Reply, then resolve — per accepted thread

For each accepted `resolve` row:

1. Post a short reply that says **what changed**. Add the commit or file if it helps.
2. Mark the thread resolved.

For `reply-only` rows (questions), post the answer. Resolve the thread only if it really needs no code change.

Do **not** add AI attribution to the reply. No "Generated by", "Resolved by Claude", "Co-Authored-By: Claude", or similar lines. Write only the useful content.

## Using MCP

Use the MCP tool to reply to each thread by its ID. Then mark it resolved.

## Using the CLI

**GitHub** — reply to the comment. Then resolve the thread with GraphQL. You need the thread node ID from Step 3:

```bash
# Reply to an inline review comment (by its REST comment id)
gh api repos/{owner}/{repo}/pulls/{number}/comments/{comment_id}/replies \
  -f body="<what changed>"

# Resolve the thread (thread node id from the reviewThreads query in Step 3)
gh api graphql -f query='
  mutation($threadId:ID!){
    resolveReviewThread(input:{threadId:$threadId}){ thread{ isResolved } } }' \
  -F threadId=<thread-node-id>
```

**GitLab** — add a note to the discussion. Then resolve it:

```bash
glab api projects/:id/merge_requests/<number>/discussions/<discussion_id>/notes \
  -f body="<what changed>"

glab api --method PUT \
  "projects/:id/merge_requests/<number>/discussions/<discussion_id>?resolved=true"
```

**Bitbucket** — use the reply and resolve commands of the installed CLI. Each CLI has different flags. If the CLI cannot resolve a thread, post the reply. Then ask the user to resolve the thread by hand.

## Using the browser

Open the PR page from Step 2. For each thread:

1. Find the thread by its file, line, and first words (saved in Step 3).
2. Click **Reply**. Type the reply. Click the button that posts it (e.g. **Comment** or **Reply**).
3. Click **Resolve conversation** (GitHub) or **Resolve thread** (GitLab, Bitbucket).

Do not click any other button. If you cannot find a thread, leave it open. Report it in Step 7.

## Do not resolve when

- Party-mode's review did not accept the change (`incomplete` / `blocked`).
- The comment is a question the user has not answered yet.
- You cannot link the change to that exact comment.

Leave those threads open. Report them in Step 7.
